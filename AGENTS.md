## Rules

- **Measure performance, don't guess.** Run `./perf.sh` after any change to sampling or views, with the panel
  closed *after* opening and closing the panel and dashboard once. Hidden SwiftUI views that keep observing
  `Monitor` have caused 20–30% CPU regressions before.
- **Views must not update while hidden.** The panel renders a placeholder while closed, and the dashboard and
  Settings windows are torn down on close. Keep it that way; don't use SwiftUI `Window` or `Settings` scenes.
- **No repeating or long-running animations**, and no `ImageRenderer` on a timer.
- **No new dependencies.**
- **Network access is opt-in only.** The update check is the one request Sonar makes, and it's off by default.
- Verify UI changes by running the app and looking at it, not only by building.
- Format and lint with `swift-format` (see CONTRIBUTING.md) before committing.
- Don't push tags or create releases by hand: merging a PR with a `Release X.Y.Z` changelog section releases it
  (see [docs/RELEASING.md](docs/RELEASING.md)). Never merge your own PRs.
